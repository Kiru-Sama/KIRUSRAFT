# KIRUSRAFT 插件开发指南

v0.0.27 起，插件系统升级为 **统一插槽（PluginManifest）+ Cordis 原生三件套**（inject 依赖门控 / provide 服务声明 / Config 配置 schema 校验）。本文档是新增插件与架构维护的权威参考。

## 1. 插件统一插槽：PluginManifest

每个插件导出 `manifest`，声明全部元数据。字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | `string` | 是 | 唯一 id（即 Cordis runtime name） |
| `kind` | `PluginKind` | 是 | `'core' \| 'ui-theme' \| 'tool' \| 'provider' \| 'gui' \| 'utility'` |
| `label` | `{ zh, en }` | 是 | 双语显示名（插件管理 UI 展示，英汉双语） |
| `group` | `PluginGroup` | 是 | 功能区：`'基础' \| '界面' \| '主题' \| '服务商' \| '工具'` |
| `inject` | `string[]` | 否 | 依赖的内核服务名（Cordis 依赖门控） |
| `provide` | `string \| string[]` | 否 | 本插件提供的服务名（声明式服务图谱） |
| `configSchema` | `StandardSchemaV1` | 否 | 配置校验 schema（挂载时自动校验+归一） |
| `providesGui` | `boolean` | 否 | 是否自带完整 GUI（主题插件的 GUI 仲裁用） |
| `protected` | `boolean` | 否 | 是否受保护（禁用需二次确认） |
| `description` | `string` | 否 | 一句话描述 |
| `apply` | `(ctx, config?) => unknown` | 是 | 插件主体 |

## 2. 挂载机制：toCordisPlugin

**不要**手写 `{ name, apply }` 挂载——那样 inject/provide/Config 全部丢失（历史 bug）。统一用：

```ts
import { toCordisPlugin } from '../core/manifest';
await ctx.plugin(toCordisPlugin(manifest), config);
```

`toCordisPlugin` 把 manifest 转成 Cordis 认识的插件对象：

```ts
{
  name: m.name,
  apply: m.apply,
  inject: m.inject,     // 激活依赖门控
  provide: m.provide,   // 激活服务声明
  Config: m.configSchema, // 激活配置校验
}
```

`src/index.ts` 和 `src/core/topology.ts` 的挂载点均已改走此函数。

## 3. inject 依赖门控

声明 `inject: ['tools', 'config']` 后，Cordis 保证：

- **依赖未就绪 → 插件保持 PENDING**（apply 不执行，bootstrap 不卡死）。
- **依赖服务出现 → 自动唤醒装载**（`reflect.notify` 机制）。
- **依赖被卸载 → 插件连带自动卸载**。

副作用须知：A 插件 `inject` B 插件提供的服务，则禁用 B 会连带卸载 A。因此：

- 服务提供方（如 update-checker 提供 `update`）若被其它受保护插件依赖，应一并 `protected: true`。
- 设计依赖时想清楚"关掉它该不该连坐"。

验证：`src/core/inject-gate.test.ts` 是真实运行时集成测试（PENDING 不执行 → 服务出现自动 ACTIVE → 顺序正确）。

## 4. configSchema 配置校验

`defineSchema`（`src/core/schema.ts`）是 StandardSchemaV1 极简同步适配器：

```ts
import { defineSchema } from '../core/schema';

configSchema: defineSchema<Config>((value) => {
  const raw = (typeof value === 'object' && value !== null ? value : {}) as Partial<Config>;
  if (raw.enabled !== undefined && typeof raw.enabled !== 'boolean') {
    throw new Error('enabled 必须是布尔值');
  }
  return { enabled: raw.enabled ?? true, root: raw.root }; // 归一：缺省补默认值
}),
```

规则：

- **必须同步**：Cordis 的 `resolveConfig` 对 async validate 抛 `TypeError('Async config validation is not supported')`。
- 校验失败：抛错 → fiber 进 `FAILED`（不崩 bootstrap，管理面板可见失败态）。
- 校验成功：返回值即归一后的 config 传给 apply。

## 5. 受保护插件

受保护判定单一来源 = 插件 manifest 的 `protected: true`（`topology.isProtected()` 读取，无硬编码名单）。当前受保护的：

```
core-services / fallback-gui / update-checker
```

- 受保护插件禁用会被拒绝（`{ ok: false, message: '... 是受保护插件，不能禁用' }`）。
- manifest 同步 `protected: true`，插件管理 UI 显示锁标识并二次确认。
- 判定标准：禁用会导致软件崩溃/无响应/核心功能缺失的插件必须受保护。

## 6. 新增插件模板

1. `src/plugins/` 下建文件（如 `my-plugin.ts`）：
```ts
import { Context } from '@deepseek-ai/cordis';
import type { PluginManifest } from '../core/manifest';

export const name = 'my-plugin';
export const inject = ['tools'];

export const manifest: PluginManifest = {
  name,
  kind: 'tool',
  label: { zh: '我的插件', en: 'My Plugin' },
  group: '工具',
  inject,
  provide: 'my-service',   // 若提供服务
  description: '一句话描述',
  apply,
};

export function apply(ctx: Context): void {
  // 用 ctx.xxx 服务注册你的能力
}
```
2. `src/index.ts` 的 `PLUGINS` 数组加一行：
```ts
import * as MyPlugin from './plugins/my-plugin';
// ...
MyPlugin.manifest,
```
3. 若需配置校验，加 `configSchema`（见第 4 节）。
4. 若禁用它会导致崩溃/无响应，加 `protected: true`（受保护判定读 manifest，无需改其他文件）。

## 7. 健壮性约定

- **核心服务逐个容错**：`core-services.ts` 的 apply 对每个服务独立 try/catch，单个服务初始化失败（如 IndexedDB 不可用）不影响其余服务注册，避免级联白屏。
- **兜底链双保险**：主题加载失败 try/catch 回退 fallback-gui；fallback-gui 自己失败也 try/catch（不崩 bootstrap，留日志）。
- **apply 内 config 用 `?? 默认值` 容错**：挂载时可能收到空对象/undefined。
- **插件失败态可见**：fiber FAILED 会被拓扑服务记录，管理面板展示，不静默。
